### 3. Top 10 recurring traps

- **Measure vs raw field in key influencers:** a measure in Analyze needs Expand by for its granularity; raw factors go in Explain by (5-2, 5-3).
- **Numeric metric with many unique values:** set Analysis type to Continuous; changing data type does not help (5-1).
- **Counting from the wrong side of a many-to-one:** aggregate the fact-table key to get order counts; the dimension key has no order rows (5-5).
- **Row context missing in measures:** a naked column argument to DATESINPERIOD errors; wrap it in MIN/MAX or iterate (4-4, 4-5).
- **Iterating the wrong grain:** AVERAGEX over transaction rows gives per-transaction averages; iterate a day-grain table (4-11).
- **Iterator table choice:** TOPN and iterators need a table; use VALUES of the dimension column to rank members (4-13).
- **Single-date vs date-window functions:** DATEADD returns one shifted date; DATESBETWEEN and DATESINPERIOD return ranges (4-6, 4-7).
- **Merge vs append, and join kind:** append stacks rows; merge adds columns; Left Anti returns unmatched rows (4-23, 4-25).
- **Load size vs refresh:** excluding from report refresh does not reduce model size; disable Enable load, and do not delete queries that other queries reference (4-25, 4-26).
- **Default summarization collapses rows:** numeric fields aggregate by default; "Don't summarize" shows each combination, nulls included (4-29).

### 4. Notable DAX / M snippets

1. **4-3 (keyed correct; disputed):** `Sales Last Quarter = IF (NOT ISEMPTY(Sales), CALCULATE ( [Total Sales], PREVIOUSQUARTER( 'Date'[Date] ) ) )`. Guards the calculation on the Sales table being non-empty.
2. **4-3 option E (also keyed correct):** `IF (ISBLANK([Total Sales]), BLANK(), CALCULATE ( [Total Sales], PREVIOUSQUARTER( 'Date'[Date] ) ) )`. Returns blank only when the current value is blank.
3. **4-4 (wrong, errors):** `DATESINPERIOD('Date'[Date], 'Date'[Date] - 1, -7, DAY)` inside a measure. The naked column has no row context.
4. **4-5 (correct):** `DATESINPERIOD('Date'[Date], MIN('Date'[Date]) - 1, -7, DAY)`. MIN gives a single anchor date.
5. **4-6 (wrong):** `DATEADD('Date'[Date], -7, DAY)`. Returns the single date set shifted back 7 days, not a window.
6. **4-7 (correct):** `DATESBETWEEN('Date'[Date], MIN('Date'[Date]) - 7, MIN('Date'[Date]) - 1)`. Returns the seven days before the current period.
7. **4-11 (wrong):** `Average Income per day = AVERAGEX('Affiliate Revenue', [Total Income])`, where `[Total Income] = SUM('Affiliate Revenue'[Affiliate Income])`. Iterates transaction rows, so it averages per transaction. The source's correct formula text is missing; it iterates a day-grain table.
8. **4-12 (keyed correct; M):** `Table.Max(Table.Group([Products], "Product", {{"Total Units", each List.Sum([Units Sold]), type number}}), "Total Units")`. Groups by product, sums units, then picks the top product. The source omits the inner braces, which are corrected here.
9. **4-13 (keyed correct):** `Top 2 Regions = TOPN(2, VALUES(Supplier[Region]), Purchase[Total Units], DESC)`. Ranks region members; the measure is evaluated per region via context transition.
10. **5-3 (measure in Analyze):** `Yearly Income (Male) = CALCULATE ( SUM ( Customer[Yearly Income] ), Customer[Gender] = "M" )`. A measure in the Analyze well needs Customer Key in Expand by.
