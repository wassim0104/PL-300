Lesson 0015

Table and column properties

Model the dataAbout 15 minSkill: pick the property that fixes a display problem

After this lesson you can set the property that fixes a display or usability problem: sort order, map geocoding, images, summarization, drill path or Q&A wording.

Why this matters for the exam

These are cheap marks: a question describes a display problem (months in alphabetical order, a map placing Paris in Texas, pictures showing as links) and one property fixes it. Match symptom to property and you are done.

Recall first

From lesson 0014: why does a calendar built from the fact table's own dates cause trouble?

Show answer

Days without transactions are missing, so the table has gaps and time intelligence misbehaves. A date table needs every day of full years.

Core idea

Properties change how the model behaves in reports, not what the data is. Memorise the symptom-to-property map.

SymptomPropertyDetail
Month names sort A to ZSort by columnSort MonthName by MonthNo. The sort column needs exactly one value per value being sorted.Sort by column.
Map misplaces a cityData categoryCountry, State or Province, City, Postal code, Latitude, Longitude help geocoding.Data categorization.
Image links show as textData category: Image URLRenders pictures in tables, cards and slicers. Web URL makes a clickable link.
Year or ID gets summedDefault summarizationNumeric columns default to Sum. Set IDs and years to Don't summarize. In a visual, "Don't summarize" shows every distinct value (blanks included).
Users want to drill Region, Manager, SalespersonHierarchyDefines drill levels. A calculated column does not.
Q&A does not know a wordSynonymsAdd "Calendar" as a synonym of the Date hierarchy. Descriptions do not affect Q&A.Q&A visual.
Excel users want the table as a data typeFeatured tableNeeds a Row label and a unique Key column.

Housekeeping that improves usability: hide technical key columns instead of deleting them when a relationship needs them; set format strings; use display folders and descriptions.

Practical example

Context. Your Date table (lesson 0014) has Month as text, and every chart shows Apr, Aug, Dec, Feb...

  1. Check the pairing: each Month name maps to exactly one MonthNo (Apr is always 4).
  2. Select Date[Month], then Column tools, then Sort by column, then MonthNo.
  3. Hide MonthNo, and set its summarization to Don't summarize.

Result. Every visual that uses Date[Month] now orders January to December, with no change to any measure.

Month = FORMAT ( [Date], "MMM" )     // name column
MonthNo = MONTH ( [Date] )              // sort column

Traps

Wrong: "Delete the ID column; I never show it." Right: If a relationship uses it, hide it instead.

Wrong: "Build a hierarchy so the map geocodes." Right: Maps need data categories. A hierarchy only adds drill levels.

Wrong: "Web URL displays pictures." Right: Only Image URL renders images.
