Lesson 0018

Iterators, context transition, counting, ranking

Model the dataAbout 20 minSkill: write an iterator with context transition

After this lesson you can write an iterator measure that evaluates per dimension member (with context transition) and choose the right counting or ranking function.

Why this matters for the exam

This is the lesson that separates "I can write SUM" from "I can write the measure the question wants". Iterators, row context and context transition produced many of the hardest practice questions (the repeated grand total, average per day, top N, rank). Counting rows versus counting orders is a near-certain easy mark.

Recall first

From lesson 0017: in a table by Category, CALCULATE ( [Revenue], ALL ( Product[Category] ) ) returns what on each row, and what would ALLSELECTED change?

Show answer

ALL returns the grand total of all categories on every row (it also strips slicers). ALLSELECTED returns the total of the categories left by the slicers and page/report filters.

Core idea

Iterators (the X functions: SUMX, AVERAGEX, MINX, MAXX, COUNTX, RANKX) walk a table one row at a time and evaluate an expression in row context for each row, then aggregate the results.DAX overview; every function is listed on DAX Guide. Row context only lets the expression read the current row's columns. It does not filter any table, and it does not flow to related tables.

So in a card visual (no filters), MAXX ( Product, SUMX ( Sales, Sales[Qty] * Sales[Price] ) ) runs the inner SUMX once per product, but each run sees all Sales rows because nothing filtered Sales. Every iteration returns the grand total, and the max is the grand total.

Context transition

Context transition is CALCULATE turning the current row context into an equivalent filter context. A measure reference carries an implicit CALCULATE, so referencing a measure inside an iterator triggers it automatically.CALCULATE: "when called in a row context, CALCULATE transitions the row into filters".

Two fixes for the repeated total: write MAXX ( Product, [Total Sales] ), or wrap the inner expression in CALCULATE ( SUMX ( ... ) ). A transition filters on all columns of the current row, so in a table without a unique key, identical rows are counted together; iterate a dimension with a key or VALUES of one column.

Moving along relationships in row context

  • RELATED ( Dim[Col] ): from a row on the many side, read a column on the one side (RELATED).
  • RELATEDTABLE ( Fact ): from a row on the one side, return that row's many-side rows, ready for COUNTROWS or SUMX.

Grain, counting, ranking

  • Grain = what one iterated row represents. Average per day: AVERAGEX ( VALUES ( 'Date'[Date] ), [Total Income] ), one value per day. AVERAGEX over transaction rows averages transactions, a different number.
  • Counting. COUNTROWS ( Sales ) counts rows (order lines). DISTINCTCOUNT ( Sales[OrderID] ) counts orders. COUNTA counts non-blank values in a column.
  • TOPN ( n, table, orderBy, [order] ) returns a table, so use it inside CALCULATE or as a calculated table. TOPN ( 2, VALUES ( Supplier[Region] ), [Units], DESC ) ranks regions, not rows. Ties can return more than n rows (TOPN).
  • RANKX ( table, expression, [value], [order], [ties] ). Order defaults to descending (highest = 1). Ties default to Skip; Dense does not skip numbers (RANKX).
  • In a measure, a bare column with no aggregation or iterator is an error. Aggregate it: MIN ( 'Date'[Date] ).

Practical example

Context. A table lists products. You need each product's sales, the best product's sales on a card, last three transactions' total, and an order count.

Best Product Sales = MAXX ( VALUES ( Product[Name] ), [Total Sales] )   -- transition via the measure
Last 3 Txn Total   = CALCULATE ( [Total Sales], TOPN ( 3, Sales, Sales[OrderDateKey], DESC ) )
Orders             = DISTINCTCOUNT ( Sales[OrderID] )
Product Rank       = RANKX ( ALL ( Product[Name] ), [Total Sales], , DESC, Dense )

Why it works. VALUES ( Product[Name] ) gives one row context per product; the measure reference transitions it to a filter on that product, so each iteration returns that product's sales and MAXX keeps the best. TOPN returns a table of three Sales rows, which CALCULATE uses as a filter, so [Total Sales] covers only those rows. DISTINCTCOUNT counts each OrderID once even when an order has several lines. RANKX over ALL ( Product[Name] ) ranks each product against the full list, then the measure runs per product via transition, with no gaps after ties.

Traps

Wrong: "Row context from Product filters Sales inside SUMX." Right: It does not. Use a measure reference or CALCULATE to transition the row to a filter.

Wrong: "COUNTROWS ( Sales ) counts orders." Right: It counts lines. Use DISTINCTCOUNT ( Sales[OrderID] ).

Wrong: "Rank or top N needs DESC for highest values." Right: Both TOPN and RANKX already default to descending. Add ASC when you want the lowest, and choose Dense if ranks must not skip.
