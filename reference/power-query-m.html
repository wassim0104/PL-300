2. Join kinds

A is the first table in the merge, B the second. Shaded means the rows kept. The M name is the last argument of Table.NestedJoin or Table.Join. Lesson 0008.

“Customers with no orders” or “items missing from the other list” means an anti join. “Everything from both” means full outer. A merge adds columns; an append adds rows.

3. Snippets

Parameterised source

Server and database come from Power Query parameters, so dev and prod differ by a parameter value only (lesson 0004). Lesson 0004

let
    Source = Sql.Database(ServerName, DatabaseName),
    FactSales = Source{[Schema = "dbo", Item = "FactSales"]}[Data]
in
    FactSales

Remove columns by prefix

Drops every column whose name starts with a prefix, even when new ones appear later. Lesson 0006

let
    Source = Orders,
    ToDrop = List.Select(Table.ColumnNames(Source), each Text.StartsWith(_, "tmp_")),
    Result = Table.RemoveColumns(Source, ToDrop, MissingField.Ignore)
in
    Result

Replace nulls

Replace null with 0 in chosen columns (use Replacer.ReplaceText for empty strings). Lesson 0006

Table.ReplaceValue(Source, null, 0, Replacer.ReplaceValue, {"Discount", "Freight"})

Latest row per group

Group with All Rows, then take the newest record with Table.Max. Table.Max returns a record. Lesson 0010

let
    Source = Sales,
    Grouped = Table.Group(Source, {"CustomerID"}, {{"AllRows", each _, type table}}),
    Latest = Table.AddColumn(Grouped, "Latest", each Table.Max([AllRows], "OrderDate"), type record),
    Expanded = Table.ExpandRecordColumn(Latest, "Latest", {"OrderID", "OrderDate", "Amount"}),
    Result = Table.RemoveColumns(Expanded, {"AllRows"})
in
    Result

Parse JSON and expand

A JSON array of records becomes a list; convert to a table, then expand records and nested lists. Lesson 0009

let
    Source = Json.Document(File.Contents("C:\Data\orders.json")),
    ToTable = Table.FromList(Source, Splitter.SplitByNothing(), {"Order"}),
    Orders = Table.ExpandRecordColumn(ToTable, "Order", {"id", "customer", "lines"}),
    Lines = Table.ExpandListColumn(Orders, "lines"),
    Result = Table.ExpandRecordColumn(Lines, "lines", {"sku", "qty"})
in
    Result

Anti join: rows with no match

Customers who never ordered. Merge, keep the left-anti result, then drop the helper column. Lesson 0008

let
    Joined = Table.NestedJoin(Customers, {"CustomerID"}, Orders, {"CustomerID"}, "Orders", JoinKind.LeftAnti),
    Result = Table.RemoveColumns(Joined, {"Orders"})
in
    Result

4. Load and reuse

Load settings

  • Enable load off: the query is a staging step and is not loaded into the model (its name shows in italics).
  • Include in report refresh off: the query is loaded but skipped by Refresh all and by scheduled refresh.
  • Disable load for lookup and helper queries to keep the model small.
Lesson 0011

Reference vs duplicate

  • Reference: new query that starts from another query's output. Upstream changes flow through; one source read can be reused.
  • Duplicate: independent copy of all steps. Later edits to the original are not picked up.
  • Reuse across several models: a dataflow.
Lesson 0011

5. Query folding checklist

Usually folds

  • Filter rows, remove or choose columns, rename, sort
  • Group By with standard aggregations
  • Merge of two tables from the same source
  • Append of tables from the same source
  • Change type (most types)

Usually breaks folding

  • Table.Buffer, index column, custom M functions the source cannot translate
  • Merge or append across different sources
  • Pivot, and Group By with All Rows
  • Any step after a hand-written native query (unless folding is enabled for it)

How to check: right-click a step and look at View Native Query. If it is greyed out, that step did not fold. Put foldable steps first. Folding needs a source that can run queries, such as a relational database; it never applies to Excel or CSV files. Lesson 0011

6. Profiling cheat lines

  • Profiling uses the top 1,000 rows by default. Switch to Column profiling based on entire data set in the status bar to scan everything.
  • Column quality: % valid, error and empty. Column distribution: distinct and unique counts with a histogram. Column profile: full statistics plus value distribution.
  • Distinct counts each different value once. Unique counts only values that appear exactly once. A key column should have distinct = unique = row count.
  • Empty string and null are different; a column can look clean and still hold blanks (trim and replace them).
