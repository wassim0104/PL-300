Lesson 0001

The Power BI landscape and the PL-300 exam

ManageAbout 15 minSkill: name the right item and tool

After this lesson you can name the Power BI item that meets a business need (semantic model, report, dashboard, app, workspace) and the tool where it is built (Desktop or service).

Why this matters for the exam

Every PL-300 question assumes you know which item lives where. Mix up a report and a dashboard and you lose easy points in all four domains. The exam also uses long case studies and Yes/No series, so knowing the format is worth a few marks on its own. Domain weights and the 700/1000 pass mark: PL-300 study guide.

Core idea

Power BI Desktop is the free Windows authoring tool. It holds Power Query (Get/Transform), Model view, DAX and the report pages, and it saves a .pbix file. Publishing a .pbix to a workspace in the Power BI service creates two items: a semantic model (formerly "dataset") and a report.Old exam text says "dataset". It now means semantic model. See service basic concepts.

ItemWhat it isBuilt in
Semantic modelData, relationships, measuresDesktop
ReportOne or more interactive pages on one semantic modelDesktop or service
DashboardOne canvas of pinned tiles, can span several reportsService only
AppChosen items from one workspace, packaged for read-only consumersService
WorkspaceShared place to work; roles Admin, Member, Contributor, ViewerService

Licences: sharing in shared capacity needs Pro or Premium Per User. Free-licence users can view only when content sits in Premium or Fabric capacity (F64 or larger).

The exam has four domains: Prepare 25–30%, Model 25–30%, Visualize and analyze 25–30%, Manage and secure 15–20%. You need 700/1000. Question types include case studies, Yes/No series, drag-and-drop and hotspot. In a Yes/No series one scenario repeats with different solutions, so judge each solution on its own.

Practical example

A sales director wants one screen with KPIs from the Finance and Sales reports, available on her phone.

  1. Open each report in the service.
  2. Pin the KPI visuals to one new dashboard.
  3. Open the dashboard in the mobile app.

It works because a dashboard collects tiles from many reports, whereas a report is bound to a single semantic model.

Traps

Wrong belief: Dashboards can be built in Desktop. Correct rule: dashboards exist only in the service.

Wrong belief: A report and a dashboard are the same thing. Correct rule: a report has pages and one model; a dashboard is one page of pinned tiles that can span several reports.

Wrong belief: "Dataset" in old text is a different item. Correct rule: it is the former name of the semantic model.
