* A Contributor can update the app only if Admins or Members allow it. In the last row a tick means RLS applies: only Viewers are restricted. Roles can go to users, security groups, Microsoft 365 groups and distribution lists; someone in several groups gets the highest role. The Viewer role sees all workspace content, so it is not “access to selected items”. Least privilege for read-only access: an app, or share to a group.

Contributor cannot publish the app or add users: that needs Member (T07). RLS does not restrict Admin, Member or Contributor (T02).

4. Row-level security (RLS)

  1. Desktop › Modeling › Manage roles: define roles with DAX table filters.
  2. Publish the model to the service.
  3. Service › semantic model › Security: add members. You cannot assign members in Desktop.
  4. Test as role. For dynamic RLS, test as the person.
  • Static: [Region] = "West". Dynamic: [Email] = USERPRINCIPALNAME(), one role for everyone. In Desktop USERNAME() returns DOMAIN\user, so prefer USERPRINCIPALNAME().
  • Several roles for one user are additive (union). Filters on several tables inside one role combine with AND. For an intersection, put both filters in one role (T01).
  • Role members: users, security groups, mail-enabled security groups, distribution groups. Not Microsoft 365 groups. Manage membership in Microsoft Entra groups, so a region change is a group change, not a DAX change (T05).
  • Direction: filters flow one way unless “Apply security filter in both directions” is ticked on the relationship (T04).
  • Who: Viewers, app consumers and shared-item recipients, even with Build. Not Admin, Member or Contributor.
  • Live connection to Analysis Services: define RLS in the AS model. DirectQuery can use the source’s own security with SSO.

6. Sensitivity labels and endorsement

  • Sensitivity labels (Microsoft Purview Information Protection) flow downstream (model, report, dashboard, new content) and persist with encryption on export to Excel, PowerPoint and PDF. RLS and OLS do not protect exported files; labels do (T11).
  • Promoted: any contributor can promote. Certified: only reviewers the admin authorises; ranked first in discovery. Endorsement is a quality signal, not access control.

7. Export settings

Per report: None, Summarized data only, Summarized and underlying data. Underlying data also needs Build on the model. A tenant admin setting limits what report authors can choose. RLS and model permissions do not stop export of what a user can see.
