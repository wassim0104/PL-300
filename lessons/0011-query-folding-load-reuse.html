Lesson 0011

Query folding, load settings and query reuse

Prepare the dataAbout 20 minSkill: keep refreshes fast and the model lean

After this lesson you can keep refreshes fast and the model lean by folding filters to the source, configuring load, and reusing queries the right way.

Why this matters for the exam

Questions on folding, Enable load and Reference versus Duplicate are subtle: two options sound alike and only one is correct. They recur across the practice sets and connect to performance and model size, so a clear mental model wins several marks.

Recall first

Which Group By operation returns the whole row with the largest value?

Show answer

All Rows, followed by Table.Max, which returns a record.

Core idea

Query folding means Power Query translates your steps into one native query (for example SQL) that runs at the source, so less data moves. Query folding basics.Glossary: Query folding. Check it with right-click on a step, View Native Query (greyed out does not prove there is no folding), the folding indicators, or Query Diagnostics. Performance Analyzer does not show folding. Once a step cannot fold, later steps cannot either, so put foldable filters first.

Setting or actionEffectSmaller model?
Enable load offConnection-only; not in the modelYes
Include in report refresh offStill in the model, skipped at refreshNo
ReferenceNew query built on another’s outputn/a
DuplicateIndependent copy of all stepsn/a

To cut a huge table, a WHERE in a native statement or a folding filter reduces rows at the source; a DAX FILTER or report filter still imports everything. Data reduction techniques. Use Reference to branch a staging query into a fact and dimensions; Duplicate means maintaining two copies and reading the source twice. Table.Buffer can stop repeated evaluation but blocks folding. Dataflows centralise cleaned tables, such as a standard Product dimension, for many semantic models; endorse them so others find them. Dataflows introduction.Glossary: Enable load, Reference query, Dataflow.

Practical example

A 100-million-row SQL table feeds a fact table and a store dimension. Only 2024 matters.

  1. Create All Sales with the date filter as the first step so it folds to a SQL WHERE. Clear Enable load.
  2. Reference it to make Fact Sales (keys and measures only).
  3. Reference it again for Dim Store and Remove Duplicates on the store columns.
Source = Sql.Database("srv", "dw"),
Sales = Source{[Schema="dbo", Item="Sales"]}[Data],
Y2024 = Table.SelectRows(Sales, each [OrderDate] >= #date(2024,1,1) and [OrderDate] < #date(2025,1,1))

The filter runs in SQL, one staging definition feeds both tables, and the staging table never enters the model.

Traps

Wrong belief: “clearing Include in report refresh removes the data.” Correct rule: it stays in the model; only Enable load off removes it.

Wrong belief: “greyed-out View Native Query means no folding.” Correct rule: it is not proof; use the indicators or Query Diagnostics too.

Wrong belief: “Duplicate is the way to reuse a query.” Correct rule: Duplicate doubles maintenance and source reads; Reference shares one definition.
