Lesson 0019

Time intelligence measures

ModelAbout 18 minAfter this lesson you can pick the time-intelligence function that returns exactly the period a requirement describes.

Why this matters for the exam

Time intelligence is one of the most frequent DAX topics in the practice questions, and the wrong answers are always almost right: a function that returns a whole year when the requirement asks for the same month, or a shifted set when it asks for a rolling window. Learn the one-line difference between each function and you turn these into quick marks on the Model the data domain.

Recall first

Why does CALCULATE([Sales], 'Date'[Year] = 2022) work when the visual is already filtered by another year?

CALCULATE replaces the existing filter on the same column with its own filter argument (lesson 0017), so the new year wins.

Core idea

Every function below needs a proper date table (lesson 0014) and takes the 'Date'[Date] column as its date argument, never a measure.Date table rules: Microsoft Learn. They all return a table of dates that you hand to CALCULATE, or they wrap that step for you.Function list: Time intelligence functions.

RequirementUseReturns
Year, quarter or month to dateTOTALYTD, TOTALQTD, TOTALMTD (or DATESYTD in CALCULATE)1 Jan to the last selected date
Same period last yearSAMEPERIODLASTYEAR or DATEADD(..., -1, YEAR)The same selected dates, one year back
Previous quarter, same lengthDATEADD(..., -1, QUARTER)Selected set shifted one quarter back
The whole previous year/quarter/monthPREVIOUSYEAR, PREVIOUSQUARTER, PREVIOUSMONTH, PARALLELPERIODThe entire prior period
Rolling N daysDATESINPERIOD or DATESBETWEENA contiguous window ending at an anchor date

SAMEPERIODLASTYEAR is shorthand for DATEADD(dates, -1, YEAR): March 2022 becomes March 2021, and it is leap-year safe.SAMEPERIODLASTYEAR, DATEADD. Four quarters back (DATEADD(..., -4, QUARTER)) is the same as one year back. By contrast, at month level PREVIOUSYEAR returns the full prior year, not the same month.

For rolling windows, DATESINPERIOD('Date'[Date], MAX('Date'[Date]), -31, DAY) counts 31 days back from the anchor. The alternative DATESBETWEEN has inclusive bounds, so a 31-day window is MAX - 30 to MAX.DATESINPERIOD, DATESBETWEEN. DATEADD is a shift of the selected set, not a window.

Year-over-year percentage is DIVIDE([Sales] - [Sales PY], [Sales PY]). Quick measures (lesson 0020) can generate YTD, YoY and rolling averages for you.

Practical example

Business context: finance wants a monthly matrix with sales, the same month last year, year to date, the previous quarter, and a rolling 31-day total on a daily chart.

Sales PY      = CALCULATE([Sales], SAMEPERIODLASTYEAR('Date'[Date]))
Sales YTD     = TOTALYTD([Sales], 'Date'[Date])
Sales PY YTD  = CALCULATE([Sales YTD], SAMEPERIODLASTYEAR('Date'[Date]))
Sales Prev Q  = CALCULATE([Sales], DATEADD('Date'[Date], -1, QUARTER))
Sales 31D     = CALCULATE([Sales], DATESINPERIOD('Date'[Date], MAX('Date'[Date]), -31, DAY))
YoY %         = DIVIDE([Sales] - [Sales PY], [Sales PY])

Why it works: each measure swaps the date filter for a different set of dates drawn from the same date table, so every cell in the matrix gets its own correct period. Sales PY YTD reuses the YTD measure and shifts it back a year, so nothing is duplicated. DIVIDE returns blank instead of an error when the prior year is zero.

Traps

Wrong belief: PREVIOUSYEAR or PARALLELPERIOD gives 'same month last year'.
Correct rule: They return the whole prior period. Use SAMEPERIODLASTYEAR or DATEADD by -1 YEAR.

Wrong belief: DATEADD(..., -30, DAY) is a rolling 30-day total.
Correct rule: That is a shifted set of the same length, not a window. Use DATESINPERIOD or DATESBETWEEN.

Wrong belief: Subtract 365 days for the prior year.
Correct rule: A fixed offset breaks in leap years. Use year-based functions.

Wrong belief: Pass a measure or a non-date column as the date argument.
Correct rule: Pass the date column of the marked date table.
