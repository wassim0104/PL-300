Lesson 0017

CALCULATE and filter modifiers

Model the dataAbout 20 minSkill: predict CALCULATE results; choose ALL, ALLSELECTED or KEEPFILTERS

After this lesson you can predict what a CALCULATE measure returns in each cell of a visual, and pick ALL, REMOVEFILTERS, ALLSELECTED or KEEPFILTERS for % of total and fixed filters.

Why this matters for the exam

CALCULATE and its filter modifiers are the heart of the DAX questions: "what does each row show?", "which function gives % of total?", "why is the same number repeated?". Practice tests returned to them again and again. If you can trace one cell at a time (below), you can answer all of them.

Recall first

From lesson 0016: when is a measure evaluated, and in which context? And a calculated column?

Show answer

A measure: at query time, in filter context, once per cell. A calculated column: at refresh, in row context, then stored.

Core idea

Filter context is the set of column filters in force for one cell of a visual. It is built from the row and column fields of the visual, then slicers, the filter pane (visual, page, report) and anything CALCULATE adds. Every aggregation in the cell sees only rows that survive those filters, including rows reached through relationships.

CALCULATE(expression, filter1, ...) evaluates the expression in a modified filter context; it is the function that changes filter context (CALCULATETABLE is the table-returning twin). The order of work matters:

  1. Filter arguments are evaluated in the original context.
  2. If a row context exists, it is converted to filters (context transition, lesson 0018).
  3. Each filter argument is then applied to the copied context. For a given column, a plain filter replaces the existing filter on that column (other columns' filters stay); KEEPFILTERS intersects instead.
  4. The expression is evaluated.

Details: KEEPFILTERS, ALLSELECTED. Variables (VAR ... RETURN) name an intermediate value, make measures readable, and evaluate the expression once.

Practical example

Context. A table lists Category and Revenue (Bikes 600, Clothing 300, Accessories 100). A slicer selects Bikes and Clothing. You need % of total and % late orders.

% of Grand Total   = DIVIDE ( [Revenue], CALCULATE ( [Revenue], ALL ( Product[Category] ) ) )
% of Visible Total = DIVIDE ( [Revenue], CALCULATE ( [Revenue], ALLSELECTED ( Product[Category] ) ) )

% Late Orders =
VAR Late =
    CALCULATE ( COUNTROWS ( Orders ), FILTER ( Orders, Orders[ShippedDate] > Orders[RequiredDate] ) )
RETURN
    DIVIDE ( Late, COUNTROWS ( Orders ) )
Row (slicer: Bikes, Clothing)[Revenue]Denominator ALL% of Grand TotalDenominator ALLSELECTED% of Visible Total
Bikes600100060%90066.7%
Clothing300100030%90033.3%

Why. Per row the filter context is Category = row plus the slicer. ALL strips both, so it sums all three categories (1000) and the visible rows no longer add to 100%. ALLSELECTED strips only the row's own filter and keeps the slicer, so the denominator is the two selected categories (900). DIVIDE returns BLANK, or an alternate result, when the denominator is zero (DIVIDE vs /). In % Late Orders, FILTER is needed because comparing two columns needs a row iterator; a Boolean filter can reference only one column.

The repeated-year puzzle. Rev 2023 = CALCULATE ( [Revenue], 'Date'[Year] = 2023 ) in a table by Year shows the 2023 figure on every row, because the Boolean replaces the row's Year filter. Wrap it as KEEPFILTERS ( 'Date'[Year] = 2023 ) and only the 2023 row has a value; other rows intersect to nothing and show blank.

Traps

Wrong: "CALCULATE ( [X], Year = 2023 ) is blank for other years." Right: It repeats 2023 on every year row. Use KEEPFILTERS to intersect.

Wrong: "ALL keeps my slicer." Right: ALL removes slicer filters too. For % of what the user selected use ALLSELECTED.

Wrong: "Plain AVERAGE gives the Sales department average." Right: Wrap it: CALCULATE ( AVERAGE ( Emp[Salary] ), Emp[Dept] = "Sales" ).
