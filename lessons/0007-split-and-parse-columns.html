Lesson 0007

Split, extract and parse columns

Prepare the dataAbout 15 minSkill: split text into typed columns or rows

After this lesson you can turn messy text (combined fields, delimited lists, text timestamps) into typed columns or rows using the fewest steps.

Why this matters for the exam

Prepare the data is a whole exam domain, and text clean-up questions turn up repeatedly in the practice sets: a combined timestamp, a comma-separated list, a column that must become a year. Each has one efficient answer, and the wrong options are usually plausible-looking type changes. Passing PL-300 means picking that one step quickly.

Recall first

Name one difference between Replace Errors and Remove Errors.

Show answer

Replace Errors keeps the row and substitutes a value; Remove Errors deletes the row. Pick by whether the requirement says to keep all rows.

Core idea

Split Column offers several modes. By delimiter is the default and produces new columns; under Advanced options you can choose into rows instead, which is the answer to “one product per row” when a cell holds “Pen, Ink, Pad”. Split columns by delimiter.Other modes: by number of characters, by positions, and by transition (lowercase to uppercase, digit to non-digit), which is the one for camelCase names and codes.

Requirement saysUse
One value per row from “A, B, C”Split by delimiter, into rows
Break “orderDate” into wordsSplit by lowercase-to-uppercase transition
Text “2018-12-31 at 08:59” to Date and TimeSplit by “ at ”, then set types
Build a date from a sample you typeColumn from examples
Only the year of a Date columnTransform, Date, Year (replaces the column)
One part of a stringExtract, Text before/after delimiter

A text timestamp cannot be converted straight to Date because of the extra token. Split first, then type each part. Splitting a DateTime into separate Date and Time columns also lowers cardinality, which shrinks the model (see lesson 0022); changing DateTime to Date alone throws the time away.Do the work in Power Query, not in DAX with SUBSTITUTE or LEFT: upstream transformations compress better. Glossary: Column From Examples.

Practical example

A call log has Logged = "2018-12-31 at 08:59" as text. Reports need a date hierarchy and a time-of-day analysis.

  1. Select Logged, Home, Split Column, By Delimiter, custom delimiter at , each occurrence.
  2. Set Logged.1 to Date and Logged.2 to Time.
  3. Rename the columns.
let
    Split = Table.SplitColumn(Source, "Logged",
        Splitter.SplitTextByDelimiter(" at ", QuoteStyle.Csv), {"Logged.1", "Logged.2"}),
    Typed = Table.TransformColumnTypes(Split,
        {{"Logged.1", type date}, {"Logged.2", type time}})
in Typed

It works because each part is now a clean value of one type, so the date hierarchy and a separate time column both exist and the two low-cardinality columns compress well.

Traps

Wrong belief: “change the type to Date and it will parse.” Correct rule: the “at” token causes an error; split first, then type the parts.

Wrong belief: “splitting always means more columns.” Correct rule: when the requirement says one value per row, choose the into rows option.

Wrong belief: “the year as a whole number is enough.” Correct rule: when a date hierarchy is needed, keep a real Date column.
