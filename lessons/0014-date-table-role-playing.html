Lesson 0014

Date tables and role-playing dates

Model the dataAbout 20 minSkill: build and mark a date table

After this lesson you can create and mark a common date table, then analyse a fact by two dates (order and ship) correctly.

Why this matters for the exam

Almost every time-based question assumes a proper date table, and "analyse by order date and ship date" is a favourite scenario. Knowing the date-table rules and the two role-playing patterns lets you pick the right answer quickly, and it is the foundation for time intelligence in lesson 0019.

Recall first

From lesson 0013: how many relationships between two tables can be active, and what does an inactive one need before it filters?

Show answer

One active; the rest are inactive (dashed). An inactive relationship filters only inside a measure that calls USERELATIONSHIP (guidance).

Core idea

A date table has one row per day, no gaps, covering full years, with a unique Date column. Build it with CALENDAR(start, end) or CALENDARAUTO(), or in Power Query.Date tables and CALENDAR. Then:

  • Mark as date table (Table tools) and choose the Date column. This matters when the relationship uses an integer key such as 20240131, and it makes time intelligence reliable. If the relationship is on a Date-type column, time intelligence works even without marking.
  • Auto date/time quietly adds a hidden date table for every date column. That bloats the model and cannot be shared across facts. Turn it off once you have a common date table.Auto date/time; design advice in Date table guidance.
  • Never build the calendar from the fact's distinct dates; days with no sales would be missing, leaving gaps.

Practical example

Context. Sales has OrderDate and ShipDate. Management wants a calendar from 2020 to 2026, a Year slicer, and a "sales by ship date" card.

Date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2020, 1, 1 ), DATE ( 2026, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Month", FORMAT ( [Date], "MMM YYYY" ),
    "MonthNo", MONTH ( [Date] )
)

Sales by Ship Date =
CALCULATE ( [Total Sales], USERELATIONSHIP ( Sales[ShipDate], 'Date'[Date] ) )

A rolling ten-year window that always includes this year: CALENDAR ( DATE ( YEAR ( TODAY () ) - 9, 1, 1 ), DATE ( YEAR ( TODAY () ), 12, 31 ) ).

  1. Create the calculated table above and mark it as a date table on 'Date'[Date].
  2. Relate 'Date'[Date] to Sales[OrderDate] (active) and to Sales[ShipDate] (inactive).
  3. Sort Month by MonthNo (lesson 0015) and turn off auto date/time.
  4. Add the ship-date measure.

Result. The Year slicer filters by order date; the new card shows the same slicer applied to ship dates. If a visual must show both dates side by side, switch to design B: Ship Date = 'Date' as a calculated table with its own active relationship.

Traps

Wrong: "Make all three date relationships inactive and it will sort itself out." Right: Inactive relationships filter nothing without USERELATIONSHIP measures. Keep one active.

Wrong: "Auto date/time handles two date columns with one slicer." Right: It builds a separate hidden table per column, so you cannot share one slicer. Use a common date table.

Wrong: "Distinct dates from the fact make a fine calendar." Right: Gaps break time intelligence. Generate every day of full years.
