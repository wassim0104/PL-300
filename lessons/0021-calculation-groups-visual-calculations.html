Lesson 0021

Calculation groups and visual calculations

ModelAbout 18 minAfter this lesson you can replace repetitive time-intelligence measures with one calculation group and know when a visual calculation is simpler.

Why this matters for the exam

When a question describes ten measures that each need YTD, prior year and YoY, the exam wants a calculation group, not thirty measures. Visual calculations are newer, so the questions test where they live and when to prefer them. Together they are quick wins in the Model the data domain (visual calculations are also a Visualize objective).

Recall first

A matrix needs month-end stock from daily snapshots. Which filter goes in CALCULATE?

LASTDATE('Date'[Date]), or LASTNONBLANK when the last day may have no snapshot.

Core idea

A calculation group is a table of calculation items. Each item rewrites whichever measure is in the visual, using SELECTEDMEASURE().Calculation groups. Create one in Desktop Model view (Calculation group). Doing so turns on Discourage implicit measures, so only explicit measures work with it. Put the group's column on matrix columns or in a slicer.

A format string expression lets an item such as YoY % display as a percentage. Precedence decides the order when you have several groups.

Visual calculations are DAX evaluated on the visual's own data grid, created with New calculation on a visual. Functions include RUNNINGSUM, MOVINGAVERAGE, PREVIOUS, NEXT, FIRST, LAST, COLLAPSE, EXPAND. They are stored in the visual, not the model.Visual calculations overview.

Calculation groupVisual calculation
Lives inThe semantic modelOne visual
Reused byEvery visual and every measureNothing else
Best forMany measures times many time variantsOne-off running total or versus previous row

Practical example

Business context: Sales, Cost and Margin each need Current, YTD and PY columns in a matrix. Without a calculation group that is nine measures.

-- Calculation group "Time Calc", column "Period"
Current = SELECTEDMEASURE()
YTD     = CALCULATE(SELECTEDMEASURE(), DATESYTD('Date'[Date]))
PY      = CALCULATE(SELECTEDMEASURE(), SAMEPERIODLASTYEAR('Date'[Date]))

-- Visual calculation on one monthly column chart
Running Sales = RUNNINGSUM([Sales])

Why it works: put Period on matrix columns and the three base measures on values. For each cell, the item wraps whichever measure sits there. The running total is needed on one chart only, so a visual calculation avoids touching the model at all.

Traps

Wrong belief: Dragged columns (implicit measures) work with a calculation group.
Correct rule: Only explicit measures do, which is why Discourage implicit measures is switched on.

Wrong belief: Each base measure needs its own YTD and PY measure.
Correct rule: One calculation group applies to all of them.

Wrong belief: A visual calculation can be reused in other visuals.
Correct rule: It lives in one visual. Use a measure or calculation group when many visuals need it.
